# Windows 音视频转写差异需求

适用范围和状态见 [README.md](README.md)；模型交付见 [DELIVERY.md](DELIVERY.md)。以下要求继续本地维护。

## Windows Media 输入

- 能读取 ASF/WMV 音轨并转写为文本；优先使用 Windows Media Foundation，解码失败时回退外部 ffmpeg。
- 验收：`.wmv`、`.asf` 均能得到音轨文本；MF 不能读取但 ffmpeg 可读取的输入经回退仍能转写。外部 ffmpeg 是回退路径的运行前提，不据此宣称打包自带 ffmpeg。

## 分块并行及结果一致性

- Whisper 以 30 秒分块并行推理，worker 数受可用并行度、块数及最多 8 个的既有上限约束。
- 输出按原块顺序还原，与顺序版逐条一致；多个块失败时返回最低失败块序号对应的错误，维持顺序版的错误语义。
- 验收：成功路径文本及顺序与顺序处理一致；失败路径返回首个逻辑块错误；`fulltest.py --deep` 下 mp4/wmv 的判定与转写量交叉核对不回归。
- 原文记录的 17 分钟 mp4 转换 96.7s→29.9s 是历史环境测量，作为并行需求的依据保留，不作为所有设备的硬性耗时上限。

## 验证边界

默认 `fulltest.py` 不包含音视频，必须区分默认报告与 `--deep` 报告；打包版验收必须覆盖音视频。`transcription/wmf.rs` 当前没有独立 UT，已有转换 E2E 覆盖不能证明 MF→ffmpeg 回退和多块失败顺序每次都已走到；修改这些路径时需要相应成功/失败路径自动化验证，未执行时如实记录。
