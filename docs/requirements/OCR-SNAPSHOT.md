## 通道定义与隔离

- **SNAP-01（第二套 OCR 能力）** Xberg 提供与文档 OCR 并列的第二套 OCR 能力「截图 OCR」：输入一张图像，输出布局保真纯文本及可选的结构化文字框记录。文档 OCR（`ocr` 配置块、`paddle-ocr` 后端、pp-ocrv6 tiny、文档转换行为）保持现状不变；截图通道不进入 `ocr.backend` 后端选择集，文档通道也不因截图通道的存在改变默认值、模型、性能或输出。两通道各自使用独立配置与模型会话；隔离不意味着分进程，必须遵守 [WORKER.md](WORKER.md) 的唯一 Xberg 进程及双场景并发要求。
- **SNAP-02（模型集命名）** 截图模型集显式命名为 `snapshot-pp-ocrv6-medium-det-textsnap`（2026-10-16 由 `snapshot-pp-ocrv6-small-textsnap` 改名，用户授权换型），由检测、识别、有序字典三个成员成套组成；manifest 条目、磁盘缓存路径、引擎会话键均与文档 tiny / v6 small 互不共享、互不别名。
- **SNAP-03（字节固定）** 模型字节固定为（2026-10-16 换型，用户授权「det medium + rec small」）：det 为 RapidAI 对 `PP-OCRv6_det_medium` 的 ONNX 导出 62,119,454 字节 / SHA-256 `92078b7355007ccfffcd4c8cd441a3afd4538904d06881b29a155e1e679907c2`（source_url 指向 ModelScope `RapidAI/RapidOCR` 仓库对应文件，SHA 钉定防漂移）；rec 沿用 TextSnap 转换产物 `PP-OCRv6_small_rec/inference.onnx` 21,148,338 字节 / `3e3def686ac9a1676b59bc9749ad896263d8f68b53f352060774de359a2e23ed`；有序字典沿用原 `inference.yml` 派生（`ab078671bb49f06228eadccd34f1bb501e157f7a047095ffb943ba81512c77d1`），18708 字、74,947 字节 / `b5f2bfe2bdd9448429e3e82b51c789775d9b42f2403d082b00662eb77e401c5d`。换型依据：真实 UI 截图对照（`.tmp/snap-bench/corpus/real_ui.png`）上 det medium 修复密集小字区的检测框截断（内容错误 43 → 11），合成语料代价 0.440% → 0.590%；rec medium / v5 server 等更大识别器实测均净负，不采用。不使用 Xberg HF 仓库中的 v6 tiny 或 v6 small 导出产物替代 det；不重新导出、量化或改权重。
- **SNAP-04（显式选择，无自动回退）** 截图通道只能经显式配置或专用接口选择；模型缺失、摘要不符、成员错配时明确失败。不存在「同属 PP-OCRv6 就回退/替代」的任何路径；文档通道与截图通道不互相回退、不互相覆盖、不共享实例。
- **SNAP-05（错配拒绝）** 至少以下情形必须报错且不推理：det/rec 任一文件缺失或 SHA-256 不符；字典与 rec 模型不成套（如 tiny 字典配 small rec、字典换行/编码被改）；把文档 tiny 模型配置为截图模型集或反之；CTC 类数与「blank + 18708 字 + 尾部空格」的 18710 类约定不符。
- **SNAP-06（CTC 对应固定）** 识别解码的索引映射固定为：索引 0 = CTC blank，索引 1..18708 = 原字典顺序，索引 18709 = 尾部空格；不增删字符、不重排、不去重、不混配字典。

## 行为合同（承接 SNAP2TEXT O-23～O-28 与附录 B）

- **SNAP-07（推理约束，O-23）** 固定 CPU 推理、10 个算子内线程、顺序执行；只运行指定 det/rec，不运行文档方向分类、去畸变或文字方向分类模型。预处理、透视裁剪、后处理与 CTC 解码与原行为对齐；不以模型名和阈值相同代替等价验证。
- **SNAP-08（瓦片，O-24）** 任一选区边长大于 1216 像素时按最大 1216×1216、相邻 128 像素重叠生成瓦片并覆盖右/下边界；小选区单次检测。检测参数固定 `limit_type=max`、`limit_side_len=1216`、`thresh=0.3`、`box_thresh=0.5`、`unclip_ratio=1.5`；检测框映射回原选区全局坐标；不以缩小整图替代分块。瓦片尾部、内部边缘等确定性细则按 SNAP2TEXT 附录 B 执行。**2026-10-16 增补（用户授权）**：每瓦片在 DBNet 框之外追加「辅助细线检测」（`backend/line_detect.rs`）：对高度 ≤4px、跨度 ≥48px 且上下 4px 隔离、未被既有检测框覆盖的长水平墨迹带合成候选框（固定分 0.5），用于恢复 det 概率图无响应的表格 `----` 分隔行/下划线行；合成框走既有全局映射、接缝合并、重裁识别链路，识别为空时按既有语义丢弃（实线边框无害）。
- **SNAP-09（接缝合并、去重与重裁，O-25）** 先合并跨瓦片接缝片段，再按 IoU ≥ 0.4 或交集/较小面积 ≥ 0.6 的传递关系去重；合并后的文字框必须从原始选区重新裁剪再识别，不得拼接已识别文字代替重裁。保留优先级、接缝判定与「合并候选边缘量重算」等附录 B 细则。
- **SNAP-10（方向与批量识别，O-26）** 四边形透视矫正后批量识别，batch 固定 8；竖排疑似（高宽比 > 1.3）加试 90°/270°，普通框首试分数 < 0.5 加试 180°，平局决胜按附录 B；`text_rec_score_thresh=0.0` 只丢空串。小裁剪增强（高 < 20 像素 2× 放大）与密集代码拉伸重试按附录 B 迁入。**2026-10-16 第二次增补（用户授权）**：超宽裁剪在识别 imgW 触发钳制分支（未钳制 `imgW = int(48 × w/h)` ≥ 2×3200，钳制后横向压缩系数 < 0.5）时，按 `imgW / 3200` 等分拆段识别并按段序拼接文本（分数按段文本长度加权平均，空段计 1，全空段分数 0）；段数 < 2 或零高不拆（零高由既有 InvalidCrop 拒绝）。压扁单次前向实测整行丢失行内细笔画（长行语料 `|`），分段后恢复；无超宽裁剪时路径逐字节不变。**2026-10-16 第三次增补（用户授权）**：定稿识别分数下限 `MIN_TEXT_SCORE = 0.6`——`assemble_spans` 中选中尝试分数低于该值的非空文本整条丢弃（布局文本与 records 输出同步排除）。实测依据：16 样本全部真值文本最低识别分 0.780（line_detect 合成破折号行）、真实 UI 截图真值最低 0.95，低于 0.60 者全部为图标形似噪声（窗口钮等读成单字）；启用后 15 样本合成语料输出逐字节不变，真实 UI 样本清除全部低分噪声框。识别分 ≥ 0.6 的形似图标（如放大镜读成 `Q`、分数 1.00）无通用安全信号，不在射程内。**2026-10-17 第四次增补（用户授权）**：①`MIN_TEXT_SCORE` 0.60→**0.70**（识别插值分层改变分数分布后重扫：0.70 剔除 real_ui 中识别分 0.62–0.68 的图标噪声 `②-□×`/`φAi`，0.75 起误伤真值回升 1.296%，0.78 立即丢弃 0.780 的破折号行真值、table 回退 16%）；②行首标点扩展重试（`lib.rs` `punct_extension_retry`，门控与实测依据见文末第四轮记录）。
- **SNAP-11（行聚类，O-27）** 按基线、中心与垂直重叠聚类行（垂直重叠 ≥ 0.45 或基线差 ≤ 正文中位字高 × 0.5）；行内按全局 x 排列，跨栏 y 相近的文字仍并入同一行并以空格保留栏距。
- **SNAP-12（网格布局文本，O-28）** 半角网格按「框宽 / Unicode 显示单元数」截尾中位数估算（EAW W/F 计 2、其余计 1、组合字符计 0）；x 与间距按网格四舍五入为空格、碰撞后移；y 网格按正文中位行距保留空行；只裁公共上/左外边距，保留缩进与内部空格，去行尾空格，不追加结尾换行；控制字符转空格。舍入、纵向间距、行归属平局等细则按附录 B。**2026-10-16 修订（用户授权）**：y 网格的空行判定由「相对首行基线的全局累积取整」改为「逐间隙推进」——行号 = 上一行号 + max(1, round(相邻基线差 / 中位行距))；均匀行距文档不受影响（中位行距取自相邻行距本身），段落间离群空隙不再因累积舍入误差丢空行。
- **SNAP-13（输出）** 布局文本按 SNAP-08～SNAP-12 生成；同一输入在 JchTools 参考实现（snap-ocr-core + 同字节模型）与 Xberg 截图通道上的最终文本在纯逻辑用例上逐字符一致，在真实截图对照上满足 SNAP2TEXT 附录 C 的质量口径（正文 CER ≤ 2%、布局锚点偏差 ≤ 一个半角单元或一行）。**2026-10-16 修订（用户授权）**：识别质量优先于与参考实现的逐字符一致——本通道保留 SNAP-03 钉定模型字节与 SNAP-07～SNAP-12 的参数框架，但 SNAP-08 增补的辅助细线检测与 SNAP-12 的逐间隙行推进使输出可偏离参考实现；纯逻辑 UT（管线/布局层）仍全部保持，参考实现逐字符对照不再作为本通道的回归门。

## 本地调用接口

- **SNAP-14（worker 协议扩展）** `xberg worker`（见 [WORKER.md](WORKER.md)）新增 `ocr_snapshot` 命令：请求携带图像字节（base64，PNG 或等价无损编码）与选区元数据，不要求也不鼓励调用方落盘——截图内容只驻内存。响应为单行 JSON：成功 `{"id":..,"ok":true,"text":"<布局文本>",...}`；失败 `{"id":..,"ok":false,"error":"<一行原因>","error_kind":"<错误类别>"}`。并发调度、进程内模型常驻、请求关联与退出语义遵循 [WORKER.md](WORKER.md)；文档转换进行中必须能在同一进程执行截图推理。
- **SNAP-15（错误类别）** 至少区分：`model_not_ready`（未加载/加载中）、`asset_invalid`（缺失或校验失败）、`input_invalid`（图像无法解码）、`no_text`、`cancelled`、`internal`。错误消息不含图像内容。调度层的协议级错误 `duplicate_id`（在途 `id` 重复被拒绝，任意命令均可能携带）不在此引擎类别枚举内，见 [WORKER.md](WORKER.md)。
  首个有效截图请求保留惰性加载并等待其结果；已有截图请求负责冷启动、模型尚未加载或加载中时，后续截图请求立即返回 `ok:false` + `model_not_ready`，不排入推理队列、不保留图像。调用方通过 `snapshot_state` 观察状态，就绪后重试；加载失败仍由负责加载的请求报告 `asset_invalid`，下一次请求可以重试加载。就绪后的普通推理保持有界排队。
- **SNAP-16（取消边界）** 客户端在请求处理期间断开 stdin/管道连接时，worker 在瓦片或识别批次检查点终止该请求并回收资源；已断开请求的结果不得再写出，也不得把终止伪造成成功。检查点粒度与 SNAP2TEXT O-19 一致（取消不是错误）。
- **SNAP-17（状态查询）** worker 协议提供截图通道状态查询（未初始化 / 加载中 / 就绪 / 错误 + 错误摘要），供调用方在模型常驻加载期间提示等待（对应 SNAP2TEXT O-13）。
- **SNAP-18（CLI 验收入口）** 提供等价 CLI 子命令（如 `xberg snapshot-ocr --image <路径> --json`）用于开发验收与调试；它不是文档通道的后端开关，也不能改写 SNAP-04 的选择语义。
