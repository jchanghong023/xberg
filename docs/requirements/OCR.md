# 图片抽取与 OCR 差异需求

本文件是 OCR 默认行为、布局输出和资源约束的唯一需求位置。适用范围和状态见 [README.md](README.md)，落盘封装与引用见 [FORK.md](FORK.md)，离线模型供应见 [DELIVERY.md](DELIVERY.md)。

## 图片与后端默认设置

- PDF 默认抽取图片；省略 `images` 段仍抽取并处理图片。图片 OCR 文本默认追加到输出，显式 `extract_images = false` 能关闭图片输出；图片输出与 OCR 处理是独立开关，不将关闭输出解释为关闭所有 OCR。
- 内嵌图片默认 OCR，包括没有 `ocr` 配置块的情况。`ocr_embedded_images` 未设置时视为开启，显式 `false` 可关闭；图片处理还须尊重相应 OCR 配置，不能因不输出图片字节而跳过已启用的 OCR。
- 编入 `paddle-ocr` 时默认后端为 PaddleOCR pp-ocrv6 tiny；否则为 Tesseract。标准包保留 Tesseract 作为可显式选择的后备，允许 `--ocr-backend tesseract` 或 `ocr.backend` 覆盖。
- 未显式配置 `pipeline` 时，不自动合成 Tesseract/PaddleOCR 混合回退链；默认或显式选择的单后端都不能被悄悄扩展。需要混合时由调用方显式配置。
- Tesseract 语言代码在各消费者使用前统一解析为语言包名，例如 `zh` → `chi_sim`；已有包名保持可用。
- 验收：缺省 PDF/Office 转换具有抽图及 OCR 结果；关闭图片输出和关闭内嵌 OCR 分别生效；缺省后端与显式选择一致；未配 pipeline 时 `effective_pipeline()` 为 `None`；短语言码与对应包名效果一致。

## 图片文字的相对位置与完整性

- 出厂能力不使用 layout/table 模型，不编入或分发 RT-DETR/TATR。图片输入只走 OCR，其版面信息由 `text` 围栏中的等宽网格承载，不要求借助表格模型生成 Markdown 表格。
- 每张图片的 marker 是独立段落，其后紧跟该图的 OCR `text` 围栏。`ocr_text_only` 开启时仍保留 marker 与 OCR 围栏这两部分；原有位置关系不得被渲染或去重破坏。
- 优先按 OCR 行的空间位置还原行列与相对间距，中文按双列宽处理。整行放不下或超出网格行数限制时，整体回退到完整平文本，绝不截断或静默丢行；不将当前内部网格容量固化为产品上限。
- 独立 `image/*` 输入与文档内嵌图片适用相同规则。独立图片的围栏必须含列对齐行：同一视觉行的多个文本块落在同一输出行，并保持相对列位置。
- 验收：marker 与所属围栏相邻且归属正确；围栏内原文不被重写；OCR 文本不因段落去重丢失；拒绝网格布局时平文本仍完整；独立图片及内嵌图均满足相同行列与完整性要求。

## 并发与资源边界

- PaddleOCR 支持多个并发引擎实例，避免单会话互斥让图像处理完全串行；每个模型键的实例槽位有上限，既有默认上限为 8，以限制模型权重和 ORT arena 复制带来的内存增长。
- `ConcurrencyConfig::max_threads` 的活动线程预算同样约束 PaddleOCR 模型会话，不能只约束其他 OCR 后端。并发不能突破预算或改变内容质量。
- 验收：多图片处理可使用多个实例，实例数有界，线程配置能够传到会话；转换质量报告无新增问题或同码恶化。原有吞吐测量仅是设计依据，不设跨硬件的固定速度指标。
